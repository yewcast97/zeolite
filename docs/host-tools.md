# Host Tools

Some work needs the Mac: its GPU, its compilers, an application that runs nowhere else. A sandbox that is given **Host Tools**, in its Setup beside its Shared Folder, lets its agent run programs of this Mac. Each runs under the **Host Tool Wall**, a Seatbelt profile that leaves it the Mac's installed software to read, the sandbox's Shared Folder to work in, and nothing else of this Mac.

- **One tool, for every program.** The workstation's supervisor writes an MCP server, `macos`, into every known agent's registry: to an agent it is a place where a program runs under macOS, within bounds, and it is named for that. Its one tool, `run`, takes a program and its arguments, the folder of the Shared Folder to start in, variables to add, and how long the run may take. It answers with the program's exit status and the start of what it printed. There is no list of programs to keep: what is installed on this Mac under `/Applications`, in Homebrew or with the system can be run, and a toolchain that is not installed the agent fetches in its sandbox, built for macOS, into the Shared Folder, and runs from there. The agent's calls show under MCP Calls, as a pack's do.
- **The call crosses on the sandbox's Link**, a stream that Docker carries, as a sandbox's packets are: the app runs the supervisor's link in every workstation, and the link's standard streams are the Link. Nothing listens on this Mac, and no port of the sandbox is published. A request is checked in the workstation and again by the app, which runs it; nothing in it reaches a shell unless the agent runs one. The app refuses a Host Tool's request of a sandbox that is given none.
- **The Wall denies everything, and then allows by name**: to run and to read `/System`, `/usr/bin`, `/bin`, `/usr/lib`, `/usr/share`, the command line tools, `/Applications` and the folders of Homebrew that hold programs and libraries; to read and to write the sandbox's Shared Folder and its **Host Tool Scratch**; some fifty facts of the kernel, by name; its own processes. No home directory, no `/Users`, no `/Volumes`, no network of any kind, no service of the system's, no clipboard, keychain, screen or other program.
- **What `deny default` leaves open is closed by name.** Found by trying each from inside: the hardware's registry, with its serial number, its UUID and its network cards' addresses; the firmware's variables; the call that returns the hardware's UUID; the list of mounted volumes; what a process may learn of another, by which a tool named every program running on this Mac; and the Mac's other volumes under `/System/Volumes`, one in a folder named for this Mac alone.
- **The launch is part of the Wall.** A Host Tool has an environment the app makes and nothing of the app's own: a `PATH` of this Mac's compilers and programs, and a home directory, a temporary folder and a cache folder in its Scratch. It has no standard input. Its processes are one group, which ends when the program does or when its time is up: 10 minutes unless the call says, 25 at most. Of what it prints, 256 KiB of each stream are sent back, and four run at once for a sandbox.
- **The Host Tool Scratch** is the sandbox's own folder on this Mac, at `/Users/Shared/zeolite/hosttool.noindex/scratch/<id>`: outside every Shared Folder, which no workstation mounts, and outside your home, so that no path a tool is told carries your name. Destroy deletes it, however a tool left it: a folder made read-only and a file put under `chflags uchg`, both of which the Wall lets a tool do where it may write, are deleted with the rest.
- **The GPU is a switch**, off unless you set it. It adds to the Wall this Mac's graphics device, the system's shader compiler, and its hardware video encoder and decoder. Metal then computes and renders, and VideoToolbox encodes and decodes.
- **This Mac's name is a switch** too. Without it `uname` fails, and with it what asks a platform's name: Python's `platform` module, numpy, Blender, and the Swift compiler unless it is told its target.
- **The GPU Shim.** Two things the system's frameworks ask of a service that the Wall refuses, a small library answers in the tool's own process, loaded with the GPU switch. Where the user's cache folder is, which the system asks its directory service, and without which Metal's binary archives end the program: the Shim names a folder of the Scratch, so what Metal keeps of compiled shaders stays there. And whether a piece of code is signed as it says, twice over, which the system asks its trust service, and without which the hardware's video encoders are not found: the Shim says yes. A Host Tool is trusted with nothing, so what it believes of a signature guards nothing of this Mac's.
- **The Shim reaches what a tool starts.** It is loaded by a variable of the loader's, and this Mac's own programs, every one in `/bin` and `/usr/bin`, drop that variable for whatever they start: `sh -c "ffmpeg …"` found no hardware encoder. Nothing can be loaded into those programs, so the variable is set again after them, three ways, for a sandbox given the GPU:
  1. The **Shell Startup File**, one line that sets it. bash reads it at every start (`-c`, `-lc`, a script, a `#!/bin/bash` script), and zsh too: whatever they start has the Shim, however deep in a run.
  2. **`sh` as the program of a call is started as bash.** `sh` reads no file when it starts. On this Mac it is bash under another name, and the difference shows in a script (`echo -n`), so agents are told, and told to ask for `bash -c`.
  3. The **Homebrew Wrappers**: for each program of Homebrew's that the loader loads, a link of its name to a script that sets the variable and becomes that program, in a folder that stands in `PATH` just before Homebrew's. `PATH` passes through every program, so `ffmpeg` started by its name has the Shim whatever started it. A script of Homebrew's has no wrapper; the app reads four bytes of each program to tell, at launch and when a sandbox's Host Tools start.

Why those two services are refused, and one permission with them:

- **The trust service fetches from the network for whoever asks.** A certificate names where its issuer's is to be found, and the service goes there. Tried on this Mac: a tool under a Wall that reached the service had it request a URL of the tool's choosing, from this Mac's own address. That is a way out that no gate watches.
- **The shader compiler reads for whoever hands it an extension**, and prints the lines it could not compile. Metal asks to hand it all of `/`. Tried on this Mac: under a Wall that allowed that, a shader that included a file outside the Wall brought the file's text back in the compiler's errors. So the Wall issues an extension only for what a tool may itself read, and to write for its two folders; Metal's request for `/` is refused, and it works without.
- **The directory service knows your name**, and the names of this Mac's other accounts.

What you accept by giving a sandbox Host Tools:

- **The agent learns what is installed on this Mac**: the names of your applications, of Homebrew's packages, and what is in them. And this Mac's model, its chip, its memory, and its system's version. With the name switch, this Mac's name, which often holds yours.
- **Whatever a Host Tool reads can reach the sandbox**, by the Shared Folder. Every path the Wall lets it read is the agent's to know.
- **Nothing bounds what it uses.** It can fill this Mac's disk, through its Shared Folder and its Scratch, and take its processors and its memory for as long as a run lasts.
- **A program that leaves its process group outlives its run.** The app ends the group; a tool that puts a process in a group of its own, as a daemon does, is not ended with it. It stays under the Wall.
- **A semaphore's name is this Mac's.** The Wall allows the named semaphores Python's `multiprocessing` makes; two tools that agree on a name can signal each other through one, whatever sandboxes they belong to.
- **Sandboxes that share a folder share what their tools write there.**
- **What a tool made is the agent's.** Look at a picture it made; do not open what it made as a program. A file a Host Tool writes carries no mark that it came from elsewhere, so macOS asks nothing before running it.
- **Some programs still start without the GPU Shim**: one named by its path, or that is not Homebrew's, started by a program of this Mac's own other than bash and zsh. That is `sh` deeper in a run, `env`, `xargs`, `find`, `time`, a `#!/bin/sh` script, a Makefile's lines, Python's `shell=True`; and bash and zsh told to read no file (`bash -p`, `bash --posix`, `zsh -f`). Such a program finds no hardware video encoder, and ends where it uses Metal's binary archives. The way out is bash: `bash -c './prog'`, `SHELL := /bin/bash` in a Makefile, `executable="/bin/bash"` in Python. Not built for them: a command to put before a program, the Shim starting programs in the system's place, copies of the system's shells signed anew, a shell of the app's own.
- **Blender is signed so that nothing is loaded into it**, the GPU Shim neither. The app sets Blender's own switch that turns its binary archives off, `CYCLES_METAL_DISABLE_BINARY_ARCHIVES`, for every Host Tool with the GPU: Cycles then renders on the GPU, and compiles its kernels anew each time Blender is started, which took a minute and a half here, since it has nowhere to keep them. Giving it somewhere was tried: it takes the system's directory service, by which a tool learns your user name, and leave to write the folders in which your own Blender keeps what Metal compiled for it. A second start then took under a second; but a Host Tool would write what your own Blender runs, so it is not done. Another program signed that way that uses binary archives ends when it does.
- **The GPU's driver is in the kernel.** With the switch a tool talks to it.
- **The Wall is Seatbelt**, which macOS ships and Apple calls deprecated, and a flaw of the kernel's is beyond it. A system update changes what programs need of it: the tests try the Wall from inside, and say when one does.
- **A program that is already under Seatbelt cannot start another**: zeolite's own tests of the Carrier do not run as Host Tools.
- **The registries are as their makers documented them on 20 November 2026**, and a maker may move one: the paths and shapes are in one place, `internal/sandbox/agent.go`. An agent whose registry is elsewhere by now finds no `host` and no `sandbox`: register `supervisor mcp-bridge host`, and `supervisor mcp-bridge sandbox`, with its own client.
