# zeolite

A macOS desktop app, written in Go, that creates, configures and monitors Docker sandboxes for AI agents. The UI is MyGo native UI (`github.com/egoist/mygo`, package `ui`): views are Go, with no webview and no JavaScript.

Work in English: code, comments, UI copy, docs and commit messages.

## Maintainability rules

### Naming and concepts
- One word per thing. A thing has the same name in code, UI copy and docs, and a name means one thing. Keep a glossary that lists each term, its meaning and the synonyms never to use.
- A name says what the thing is. Use the term the domain already has before coining one. Never name something for its history (`legacy`, `old`, `new`, `v2`).
- One mechanism per job. A second cache, abstraction or code path covering the same ground is a defect: extend the existing one or replace it.
- Build nothing for needs that don't exist yet. Pick the simplest single mechanism that is correct, and generalize when the second real case arrives.

### Structure
- Dependencies point one way, from the edge towards the core. The core never imports what calls it.
- A folder groups code by the rule that governs it (what it talks to, what it writes, what job it does) and is named for that rule. No catch-all folders (`utils/`, `lib/`, `shared/`, `misc/`).
- No layout is frozen. Every refactor re-sorts what it touches: move a module to the folder whose rule governs it, rename or split a folder whose job changed, delete an emptied one.

## How the rules apply here

- The glossary is `GLOSSARY.md`. Check a new name against it, and add the term there before using it in code or UI copy.
- Imports point inward: `internal/sandbox`, `internal/palette`, `internal/cage`, `internal/chargrid` and `internal/agentfiles` import nothing of ours, `internal/pack` and `internal/probe` only `sandbox`, and the packages that do the work (`orchestrator`, `sandboximage`, `hostwatch`, `viewport`, `configstore`, `sharedfolder`, `carrier`, `hosttool`, `link`) only those two; `orchestrator` imports `sandboximage` besides, whose images it builds, `sharedfolder` and `hosttool` import `agentfiles` besides, by which each deletes what agents wrote, and `hostwatch` may import `probe`, which besides it only `cmd/gatekeeper` does, and a test at the root holds that. `internal/dashboard` uses `sandbox`, `pack` and `viewport` for their types and `palette` for its colors, and reaches everything else through the `Backend` interface it declares; `backend.go` implements it.
- A color is written once, in `internal/palette`, as a hexadecimal string; a test there fails if the package imports anything but the standard library. Sizes of text and spacing in views come from `internal/dashboard/theme.go` and the theme's `Space`, not from literals. The icon is drawn by `cmd/appicon` from the art in its source and the palette; `resources/icon.png` is its output, and a test fails when the two differ. The Masthead, at the top of the README, is drawn by `cmd/masthead` from the cage as `internal/cage` turns it, which is the Opening's, the letters in its source and the palette; `docs/masthead.gif` is its output, and a test fails when the two differ. The window's pictures are glyphs, drawn the same way from the grids in `internal/dashboard/glyphs.go`: a control that a glyph can say gets no words, only a label for whoever does not see it and a tooltip, and what takes a paragraph to explain goes behind the ⓘ glyph (`info`), not under a field. The Opening, which the window shows when the app starts, is drawn in characters too (`internal/dashboard/opening.go`): the icon's cage, turning, with the known agents' glyphs in it; its measures are the theme's, its colors the palette's, and what it is at a moment depends on nothing but the time.
- Only the main package and `internal/dashboard` import `github.com/egoist/mygo` (and `integration/`, to test the terminal). Its version is pinned in `go.mod` and upgraded in a commit of its own.
- A sandbox leaves by its Allowed Interfaces and by nothing else. Only `cmd/carrier` carries: every socket it opens is bound to the Interface in use and goes to a public address, or to a stand-in address where that Interface answers names with them, and it listens on nothing. Tests there fail on a dial that is not bound and on a call that listens; a test at the root fails if another package imports gVisor, whose version is pinned in `go.mod` and upgraded in a commit of its own. The gatekeeper carries nothing and listens on nothing; `cmd/tun` moves packets between the TUN device and its standard streams and opens no connection. The app holds no client of a protocol that carries traffic elsewhere and offers no service that does, and tracked code and docs describe none.
- A lease that ended cuts every flow, and a gate holds one only where its sandbox's Setup asks for a Hold: the ruleset then has the Hold's set and its one rule, which passes what belongs to a TCP connection that was answered and never a SYN, and has neither otherwise. Only silence leaves a Hold: what locks the gate for a reason it knows ends it with the lease, and each runs out in the kernel by itself. A name is asked, and a connection made, under the lease alone. Under a Hold the connections are kept and nothing the sandbox sends leaves this Mac: the Carrier sends on what is not the probe's only while it was told of a lease that still runs, and knows the probe's by the Probe Source Ports, which the ruleset rejects for anything without the probe's mark. Tests in `cmd/gatekeeper` and `cmd/carrier` hold each, and `integration/hold_test.go` holds it on the VM's kernel.
- A sandbox reaches an address that is not public in one case: a stand-in address, of the range `198.18.0.0/15` and of no other, by an Allowed Interface whose Setup says that names are answered with them, while that is the Interface in use. The ruleset then has the range's set and its rules, each a rule for public addresses again, and has neither otherwise; the set holds the range only by such an Interface, and gains or loses it in the transaction that ends the lease on a change of Interface, and at no other time. The Carrier carries to the range only by such an Interface, and never to an address this Mac has. A probe connects to a stand-in address only when its asker says that it is sent by such an Interface, which the gatekeeper says and the Host Watchdog never does. Where a stand-in address leads is not the app's to know. Tests in `cmd/gatekeeper`, `cmd/carrier` and `internal/probe` hold each, and `integration/standin_test.go` holds the ruleset's part on the VM's kernel.
- The app's process opens a connection to the internet for one thing: the Host Watchdog's probes, which read this Mac's physical exit addresses. Each is made by `internal/probe` on a socket bound to one of this Mac's physical Interfaces, and goes to a probe URL or to the sandbox's resolver; nothing is asked unless a running sandbox's Interface in use expects this Mac's physical exit address, or any but it. Tests in `internal/probe` fail on a socket made without the asker's socket option, on a default of `net` or `net/http`, on a proxy and on a call that listens; tests in `internal/hostwatch` fail on a dialer, listener or lookup of its own, on a second place that sets `IP_BOUND_IF` and on a second that makes a probe's client; a test at the root fails if any other package the app's process links makes a socket. Not known is locked: a heartbeat says this Mac's physical exit addresses are known only when the Watchdog has read every physical Interface within a minute, and when the Mac wakes the Watchdog forgets everything before the heartbeats resume.
- The app reads nothing in a Shared Folder. Only `internal/sharedfolder` names the root, and it makes, lists by name and deletes there without reading a file; only the main package imports it (and `integration/`, to test the real folder), and passes a folder's path to Docker and to the Host Tool Wall. Tests in `internal/sharedfolder` and at the root fail otherwise. A Shared Folder is deleted by `RemoveSharedFolder` and by nothing else, and never while a running sandbox mounts it.
- What agents wrote on this Mac's disk, a Shared Folder and a Host Tool Scratch, is deleted by `internal/agentfiles`, and how it was left keeps none of it: a folder that is read-only, and what a Host Tool put under a flag that forbids deleting it (`chflags uchg`), which the Wall lets it do where it may write, are loosened first. The package reads no file and follows no link: it names an entry by its folder's descriptor and by its own name, and a name with a separator in it is no entry's, since a path that begins with one is taken from the root of this Mac whatever folder it is given with; and its walk stays on the volume it began on, so that a disk mounted in such a tree is left as it is. Only `internal/sharedfolder` and `internal/hosttool` import it, which a test at the root holds. Its tests start themselves again in a process that may write nothing but a temporary folder of its own, and one fails where that is not in force: change the walk only with them.
- A sandbox's Home is a Docker volume in the VM, named for the sandbox's ID, that only that sandbox's workstation mounts, at `/workspace`; the image's `/workspace` is empty and the agent's. A Home is deleted by `RemoveHome` and by nothing else, never while its sandbox is starting or running, and nothing lists Homes to delete them: not the launch, not `RemoveOrphans`, not a test. A sandbox whose Home could not be deleted is not forgotten. A workstation's `/tmp` is a volume too, on the VM's disk, but one with no name: Docker makes it with the workstation and removes it with it, and `removeContainer`, the one way a sandbox's container is removed, is the one place that asks Docker to. No volume that has a name is removed that way. Tests in `internal/orchestrator`, `internal/sandboximage` and `internal/dashboard` hold each.
- No step of an image's build runs on a bridge. A workstation's image is built in the namespace of the sandbox it is built for, by way of its gate, which is waited for: its steps are a pack's. The gatekeeper's image, whose one step is the app's own, is built on the VM's own network, and no other image is. `buildImage` is the one place that asks Docker to build, and every build says where its steps run. Tests in `internal/orchestrator` hold each, against a daemon of their own, and `integration/build_test.go` reads a build's step from inside.
- A workstation has no capability, and nothing runs in one with any. No container is privileged, and the one capability any is given is `NET_ADMIN`: a gatekeeper's and the Backstop's, over their own rulesets. A test at the root holds it, and `integration/pod_test.go` reads a workstation's capabilities from inside.
- The app starts two kinds of program for a sandbox, each under a Seatbelt profile of its own: its Carrier, under the Carrier Wall, which runs nothing of the agent's; and its Host Tools, under the Host Tool Wall, which are what the agent asks to run on this Mac. A test at the root fails if a package outside its list imports `os/exec`.
- What a sandbox's agent does on this Mac, a Host Tool does, and only for a sandbox whose Setup gives it Host Tools. Only `internal/hosttool` starts one, and always under the Host Tool Wall: `wall.sb`, to which a Setup adds `gpu.sb` and `macname.sb` and nothing else. The Wall denies by default and then closes by name what that leaves open; it allows no network, no service of the system's but the GPU's own, and no write but the sandbox's Shared Folder and its Host Tool Scratch. It issues an extension only for what a tool may itself read, and to write for those two folders: one for more makes the shader compiler read this Mac for the tool. It never reaches the trust service, which fetches from the network for whoever asks, nor the directory service: the GPU Shim answers in their place. The Shim is loaded by a variable that this Mac's own programs drop for what they start, so `internal/hosttool/gpu.go` sets it again three ways and no fourth: the Shell Startup File, which bash and zsh read; `sh` as a request's program started as bash; and the Homebrew Wrappers, for a program of Homebrew's that the loader loads, never for a script. What that leaves without the Shim is pinned by the rows of `TestTheShimReachesWhatARunStarts` that expect none. The launch is part of the Wall: an environment of the package's own, no standard input, a process group that ends with the run, a time limit, bounded output. The app reads nothing a Host Tool printed, and follows no link in a Shared Folder: it passes the one on, and leaves the change of folder to the Wall's inside. A request crosses from a workstation on the sandbox's Link, a stream the Docker API carries, which `internal/link` reads and nothing else does; it is checked again by the app, and refused for a sandbox that is given no Host Tools. A Host Tool Scratch is deleted by `RemoveScratch` and by nothing else, by its sandbox's ID, and never while its Host Tools are served. Change the Wall only with a probe that fails before and passes after: tests in `internal/hosttool` try it from inside, with a control outside, and pin what it may allow.
- The app installs no agent, starts none and pairs no sandbox with one. A Terminal Session is a login shell and nothing else: `supervisor shell` takes a session's ID and no program, no text of a user's or an agent's reaches a shell, and what runs in a session its user types there. The agents the app knows are names in `internal/sandbox/agent.go`, by which it knows one that runs; their makers' installers are in `integration/agents_test.go`, and what sends each to a model in `integration/agentwork_test.go`, and neither is anywhere in the app. The app's process fetches nothing. Tests in `internal/sandbox`, `cmd/supervisor`, `internal/orchestrator` and `internal/dashboard` hold each.
- The app reads nothing a Terminal Session prints. The dashboard shows a terminal and takes from it that its program rang, sent a notification or ended, and the address of a link its user Command-clicks there: no screen, no history, no title, no link the pointer only rests on, and no word of a notification. One function takes that address (`openLink`, in `internal/dashboard/viewport.go`), and leaves no link to the terminal, which would open it with this Mac's: a web address goes to the sandbox's browser, which opens it in a new Browser Tab, only where a Pane shows that browser or one can be added that does; anything else goes to this Mac's clipboard, by its user's click, and nothing on this Mac opens it. Which agent runs in a session, the supervisor says from the names of the session's processes (`cmd/supervisor/sessionfacts.go`), and from no terminal. What a Card says of a sandbox is the app's own words. Tests in `internal/dashboard` and `cmd/supervisor` fail otherwise.
- The VM mounts the Shared Folders' root or nothing. `ExposedMacFolders` reports anything else, and a mount is the root only by the marker the app wrote in it.
- The app takes no API key, keeps none and gives a workstation none: a sandbox's config has no place for one, which a test in `internal/configstore` holds.
- An agent is told how to use a tool, and nothing of where it works: what its sandbox is, what hosts it and what its folders are, it finds out. What it is told comes by MCP, from the servers `sandbox` and `macos`: each one's instructions are its tool's description, which stands alone, is true of the tool, and says it as an agent uses it: what it is for, how it is called and what it bounds, in no word of the app's own and with nothing of how the app shows it to its user (`cmd/supervisor/state.go`, `hosttools.go`). The server `macos`, which a sandbox has only with Host Tools, is named for what it is to an agent, a place where a program runs under macOS, and says that a Mac runs it, not whose; the server `sandbox` says its tool's words and no other. What a tool answers, and why a call is refused, is said the same way, wherever it is written: what happened to the call and what the agent can do about it, with nothing of this Mac that the call did not ask for. Tests in `cmd/supervisor`, `internal/link` and `internal/hosttool` hold each. The app writes no instruction file into a Home. A raised hand is the tool `raise_hand`: it crosses the Link with its session's ID and no word, and rings no terminal. The Link is trusted for nothing: a hand is taken only for a Terminal Session the app opened in that sandbox (`Orchestrator.HasSession`).
- The sandbox's MCP servers reach an agent by its own MCP registry, which the supervisor writes at each start (`cmd/supervisor/registry.go`). Where each agent's is, and in what shape, is written once, beside the agent's name, in `internal/sandbox/agent.go`. Every entry is `supervisor mcp-bridge <name>`: the app owns exactly the entries whose command is the supervisor, replaces those, keeps no list of them, and leaves everything else in a registry as it is; a file that does not read is left untouched. The TOML library, `github.com/BurntSushi/toml`, is pinned in `go.mod` and upgraded in a commit of its own; only `cmd/supervisor` imports it.
- The tests' virtual Interface is its owner's to make, and nothing of how is in the repository: `instance_test` at the root holds what its owner wrote down of it and is gitignored. Only the fixture `integration/virtualinterface_fixture_test.go` reads it, which is gitignored too; tracked tests reach it through the hook `newVirtualInterface` and skip without it. Never copy what either file holds into tracked code, docs or commit messages.
- `.env` at the root holds the experiments' API key and is gitignored. Only one helper in `integration/agent_test.go` reads it, and only its `OPEN_ROUTER_API=` line; the key is in the environment of the one command that runs opencode in an experiment's sandbox, as `OPENROUTER_API_KEY`, the name opencode looks for; the built app's test and the test that gives every known agent a job, where an agent is started by typing, put it in the `~/.bashrc` of their one sandbox's Home, as a user would, and that Home is deleted with the sandbox; the Translator, which the second starts in that sandbox for Antigravity, has it in its environment. It is in no sandbox's config. Never copy what it holds into tracked code, docs, test output or commit messages.
- Stage files by name. Never `git add -A` or `git add .`: `TestSecretFilesStayUntracked` fails if git tracks or stops ignoring `.env`, `instance_test` or the fixture.

## Commands

```sh
go generate ./...                             # build the in-container binaries, the Carrier and the GPU Shim, and draw the icon and the Masthead; needed before anything else compiles
go tool mygo dev                              # run the app, rebuilding on change
go vet ./... && go test ./...                 # unit and view tests, no Docker
go test -tags integration -timeout 30m ./integration/      # against the Colima profile `zeolite`
go test -tags integration -timeout 30m -v -run 'TestVirtualInterface|Experiment' ./integration/   # with the fixture and its virtual Interface up: by that Interface, and a real model, in a sandbox and with Host Tools
go tool mygo build                            # package zeolite.app
```

When changing views, follow `.agents/skills/mygo-maintenance/SKILL.md` (element lifetimes, identity, threading, testing with `ui.Tester`).
